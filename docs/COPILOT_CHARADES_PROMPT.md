# Copilot prompt — 몸으로 말해요 LIVE 검토·완성

입력 위치: GitHub Copilot Chat (VS Code에서 `kuh9325/choir_vacance` 저장소를 연 상태)

세션: 새 세션 권장

권장 모델: 사용 가능한 강한 코딩 모델(Sol급)

권장 추론 강도: Medium. 기존 실시간 동기화/Cloudflare 빌드 회귀가 발생할 때만 High.

---

현재 브랜치의 `몸으로 말해요 LIVE` 기능을 저장소의 기존 점수판 아키텍처에 맞춰 검토하고 완성하라.

먼저 다음 기존 구조를 보존하라.

- Next/React + vinext + Cloudflare Workers
- `/admin`, `/display`, `/results`
- 점수판 서버 원본: D1 `event_state` id=1
- localStorage 백업
- BroadcastChannel 같은 브라우저 실시간 동기화
- 다른 기기 0.8초 폴링
- 네트워크 복구 시 서버 재동기화
- 기존 70점 점수 규칙과 테스트

몸으로 말해요는 **무배점 워밍업**이며 기존 점수 계산에 절대 포함하지 않는다.

현재 구현의 의도는 다음과 같다.

- `/admin/charades`: 진행자 제어 화면
- `/display/charades`: 프로젝터 전광판
- `/api/charades`: D1 `event_state` id=2에 독립 저장
- `lib/charades.ts`: 7개 주제/210개 제시어와 자동 스케줄러
- `components/CharadesApp.tsx`: 관리자/전광판 UI 및 실시간 동기화
- 팀명·팀색·관리자 PIN은 기존 `/api/state`에서 읽어 재사용
- charades localStorage/BroadcastChannel은 점수판과 별도 키 사용

필수 동작:

1. 동물/직업/음식/스포츠/행동/교통수단/속담 총 7개 주제, 각 30개, 총 210개 제시어를 보존한다.
2. 기본값은 5팀, 팀당 4명, 총 600초다.
3. 600초에는 시작 여유 30초, 종료 여유 20초, 팀 전환 8초씩을 포함한다.
4. 팀 수/인원에 따라 라운드 수와 턴 시간을 자동 계산한다.
5. 기본 5팀×4명에서는 2라운드/팀, 총 10턴이 되어야 하며 1라운드 담당은 1·2번, 2라운드는 3·4번이 되어야 한다.
6. 주제 기본 순환은 동물 → 음식 → 행동 → 직업 → 스포츠 → 교통수단 → 속담이다.
7. 긴 표현이 많은 속담에는 쉬운 단어 주제보다 더 긴 시간이 배정되도록 한다.
8. 모든 턴 + 전환 + 시작/종료 여유의 합은 총 배정시간을 넘지 않아야 하며 기본 설정에서는 정확히 600초에 맞는다.
9. 진행자는 제시어 뽑기, 공개/가리기, 다음 제시어, 타이머 시작/일시정지/재개, 이전/다음 팀을 조작할 수 있어야 한다.
10. 팀 교대 시 다음 답이 노출되지 않도록 제시어를 자동으로 숨긴다.
11. 전광판에는 현재 팀, 주제, 제시어, 담당 인원, 턴 번호, 턴 타이머, 전체 타이머를 큰 글씨로 보여준다.
12. 같은 세션에서는 가능한 한 같은 제시어가 중복되지 않게 한다.
13. 기존 점수판 D1 id=1을 절대 덮어쓰지 않는다.
14. 모바일 관리자와 1920×1080 프로젝터 모두에서 가독성을 확인한다.
15. 기존 `/admin`, `/display`, `/results`, 점수 계산, CSV/JSON, 오프라인 동작에 회귀가 없어야 한다.

검증 순서:

- `npm test`
- `npm run lint`
- `npm run build`
- 기본 5팀×4명×600초 자동 배정 확인
- `/admin/charades`와 `/display/charades`를 동시에 열어 조작 반영 확인
- 다른 브라우저/기기 상황을 가정해 `/api/charades` 폴링 확인
- 점수판 `/api/state` 데이터가 charades 조작 전후 동일하게 유지되는지 확인
- 새로고침 후 charades 진행상태 복원 확인
- 타이머 만료, pause/resume, 마지막 팀 종료, 초기화 확인

문제가 발견되면 최소 범위로 수정하고, 이미 동작하는 기존 점수판 구조를 불필요하게 리팩터링하지 마라. 완료 후 변경 파일, 검증 결과, 남은 리스크를 간결하게 보고하라.
